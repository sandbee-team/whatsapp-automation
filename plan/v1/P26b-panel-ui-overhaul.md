## What you are building (3-6 bullets)
- **Design system v1** in `packages/design-tokens` + `packages/ui`: OKLCH colour tokens (brand, neutrals, semantic), light + dark, radius/typography/spacing scales, and Radix-based accessible primitives — button, input, textarea, select, checkbox, switch, radio, label/form-field (react-hook-form + zod wired), dialog, sheet/drawer, dropdown-menu, popover, tooltip, tabs, data-table (TanStack Table: sort, filter, pagination, column priority, empty + skeleton rows), badge, avatar, card, KPI stat tile, skeleton, empty-state, error-state, toast (sonner), progress, stepper, OTP input, phone input, QR display, date/time picker. Every primitive has a story-like example page or a component test.
- **App shell**: collapsible sidebar (mobile: sheet), top bar with workspace + instance (number) switcher, user menu, notifications, page-header pattern (title, description, actions), breadcrumbs, command palette (cmdk) for navigation, theme toggle.
- **Auth + onboarding, start to end**: split-screen `/signup` and `/login` (brand panel + form card), `/verify-email` (resend, mailpit hint in dev), `/totp` enrol (QR + secret + OTP input) and verify, password strength, inline zod errors, disabled/loading buttons, session expiry handling; `/onboarding` as a stepper: verify email → connect a number (live QR with SSE status) → wallet/top-up → send the first message.
- **Every authed route redesigned** against the real API (`@wp/contracts`, no mocked data): `/` dashboard (KPI tiles, instance health cards, queue status, recent activity, wallet banner), `/instances` (list + detail, QR dialog with live status, pause/resume, health/link badges, Safe Mode disclosure copy), `/messages` composer (recipient picker from contacts, variables, preview, send states), `/unresolved` (data table + retry/discard actions with confirmations), `/broadcasts` (list with funnel badges; `/broadcasts/new` wizard: audience → message + variables → schedule → preflight; `/broadcasts/$id` funnel + pause/resume/cancel), `/contacts` (data table, search, add, CSV import wizard with column mapping + progress, export), `/groups` (sync + send), `/settings/webhooks` (endpoints, secret dialog, disabled state) — plus wallet/billing, team and API-key screens IF their API routes exist (verify in `app/backend/src/modules/*/routes*.ts`; if a screen has no API, say so, do not fake it).
- **Smoothness as a requirement**: skeletons on every async view, optimistic updates where the API is idempotent, toasts for every mutation, keyboard navigation (Radix), focus management, no layout shift, responsive down to 375 px, dark mode parity, sub-second route transitions (code-split routes).
- **Demo readiness + evidence**: a dev-only `pnpm demo:seed` that walks the REAL API (signup → mailpit verification → TOTP enrol → sample contacts + a draft broadcast) and prints the credentials + TOTP secret; a Playwright journey test that clicks through the whole product and saves one screenshot per route into `docs/evidence/P26b-ui/`; the founder's click-through checklist (in `docs/RUNNING-LOCALLY.md` → "Manual review checklist") updated to the new UI.
