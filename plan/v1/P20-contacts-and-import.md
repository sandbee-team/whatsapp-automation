**Goal (one line):** The tenant has an address book: client-scoped `contacts` with one normalisation module for E.164 and JID/LID, tags-as-lists, a resumable CSV import that cannot run without a recorded consent attestation and can never clear an opt-out, plus contact export and per-contact erasure.

## What you are building (3-6 bullets)
- The five client-scoped tables — `contacts`, `contact_tags`, `contact_tag_links`, `contact_imports`, `contact_import_errors` — plus the three new enums and `plan_limits.max_contacts`.
- One normalisation module in `@wp/domain`: E.164 via libphonenumber with `default_country`, `wa_jid` derivation, `jidNormalizedUser` for every provider-supplied JID, `addressing_mode` (`pn`/`lid`), and an explicit **unattributable** result instead of a guess.
- The CSV pipeline: upload → header sniff → column mapping + 10-row preview → **mandatory** consent attestation (stored with the attesting user) → resumable 500-row batches with a row cursor → result counters and a capped error report.
- The opt-out **mirror** (`contacts.opt_out_state`) written in the same transaction as the `opt_outs` insert, never in an import's `DO UPDATE` list, plus the nightly reconciler that repairs the mirror and never the authority.
- Contact export (streaming CSV, injection-escaped) and per-contact erasure (soft delete + PII scrub, audited) where the hashed `opt_outs` row survives forever.
- The refusal made mechanical: a guard that fails the build if anything under `modules/contacts/**` calls `onWhatsApp` — bulk list validation is **refused, not deferred**.

## Risks / gotchas specific to this phase
- **`ON CONFLICT` must repeat the partial index predicate.** `contacts_client_phone_uq` is partial, so `ON CONFLICT (client_id, phone_e164) DO UPDATE` will not infer it and Postgres raises *"there is no unique or exclusion constraint matching the ON CONFLICT specification"*. The only correct form is `ON CONFLICT (client_id, phone_e164) WHERE deleted_at IS NULL DO UPDATE`. This is the single most likely red in step 6.
- **`opt_out_state` in a `DO UPDATE SET` list is a compliance bug, not a style bug.** One re-imported list would un-silence everyone who said STOP. It is excluded by the SQL and asserted by `import_never_clears_an_existing_opt_out`; the mirror is only ever written by `optout-mirror.ts`.
- **`cursor_row` counts CSV *records*, not file lines.** Quoted fields may contain newlines, and a BOM/CRLF file will shift a line-counting parser by one. Resume must re-parse from the start of the stream and skip `cursor_row` **records** (or store a byte offset that the parser guarantees is a record boundary). Prove it with `a_quoted_newline_does_not_desynchronise_the_row_cursor`.
- **Never load the CSV into memory.** 10,000 rows is small; 16 MB of pathological rows on a worker holding sessions is not. Stream from the object store, one batch buffered.
- **The hash must match `opt_outs` exactly.** A second `hmac(pepper, e164)` implementation — different pepper purpose, different encoding, digits-only vs `+` — makes every opt-out join silently miss and the mirror permanently `none`. Hence the move to one file and `exactly_one_phone_hash_implementation_exists`.
- **Do not derive a `@lid` mapping.** Deriving a JID from digits is already unreliable; inventing a lid↔pn mapping mis-attributes a real person's opt-out. Store `addressing_mode`, persist a provider-supplied mapping only, and return `unattributable` otherwise. The honest UI limit (an opt-out sent from inside a group may not be attributable to a specific contact) is P24's copy, not this phase's — but the data shape that allows the truth is built here.
- **No bulk `onWhatsApp()` — refused, not deferred.** Do not add a "validate list" button, a background validator, a `queued_for_validation` column or a TODO. Invalid recipients surface at send time as terminal `invalid_recipient`. Step 9's guard exists so a future session cannot add it quietly.
- **The import writes no jobs.** Nothing in this phase enqueues, claims, reserves or sends. If a step seems to need `message_jobs`, it belongs to P23.
- **`attrs` is bounded at 2,048 bytes.** A mapping that pulls 30 columns will exceed it; the row goes to `contact_import_errors` with a reason — never silently truncated, and `raw_excerpt` is capped at 120 chars and **never logged**.
